第一层是规则执行层，包括检定、对抗、行动、反应、修正值、熟练度、伤害、治疗、状态、休息、旅行、探索、社交互动等。这一层负责回答“现在该如何判定”。

在本次修正中，规则执行层不再直接展开为某一套固定 DND_gamerule 的具体规则清单，而是被抽象为一组“规则系统生成 Skill”。每一个 Skill 都接受一个 input，该 input 可以是任意 ACGN 作品名称、世界观设定、wiki 文档、规则书文本、游戏机制说明、战斗记录、角色卡或自制模组资料；每一个 Skill 的 output 则不是固定结论，而是该作品在对应系统下可被 GraphRAG 调用的 system logic。

因此，规则执行层的核心目标不是预设“某作品一定使用哪一种骰子、数值或行动结构”，而是从输入资料中抽取、归一化并生成一套可运行的判定逻辑。该逻辑应能兼容不同作品中对近似概念的不同命名，例如“检定、判定、测试、挑战、试炼”可被归入同一类 CheckLogic；“护甲、防御、防御等级、装甲值、AC、减伤值”可被归入 DefenseLogic；“法术、技能、异能、咒术、术式、魔法、战技、宝具、能力”可被归入 AbilityExecutionLogic。

在 GraphRAG 中，规则执行层应被视为“规则运行接口层”。它负责把作品资料中的术语、数值、流程、限制、例外和裁定方式转化为统一的逻辑节点，使 LLM 在回答“现在该如何判定”时，不是直接凭语言记忆推断，而是先检索对应系统 Skill 生成的 logic，再结合当前角色、实体、场景和战役状态进行规则运行。
